## 第一章：从网页访问认识网络

### 第一部分：打开网页时发生了什么？

先从一次网页访问认识全程。这里以新建 TCP/TLS 连接的 HTTPS 访问为例；先记住各环节解决什么问题，具体机制在后面逐步展开。

#### 1. 找商家：解析 URL，查询地址

浏览器读取 `https://www.example.com/index.html`，知道主机名和资源路径；需要时通过 DNS 解析取得服务器地址。

**类比：** 先从店名查到地址，再去寄订单。DNS 需要联网查询时，同样走底层的网络传输。

#### 2. 找本地交接点：选择路由，准备链路交付

本机根据路由表决定下一跳。如果需要交给默认网关，就取得网关接口的 MAC，再向它发送帧。ARP 缓存有效时，直接复用缓存记录。

**类比：** 知道北京商家的地址之后，先把包裹交给本地能替你发货的网点。

#### 3. 建立通信：TCP 和 TLS 分别解决不同问题

- **TCP：** 通过三次握手建立连接、同步初始序号等状态，再提供可靠、有序的字节流。可以类比两端建立收发账本，后续能按编号确认和补发。
- **TLS：** 验证服务器身份、协商密钥，保护通信内容。可以类比先核验商家身份，再使用防止旁人偷看和篡改的包装。

**握手也需要运输。** SYN 等握手报文本身也要经过 IP 和链路层封装，逐跳发往对端。

#### 4. 提交订单：HTTP 表达真正的请求

```http
GET /index.html HTTP/1.1
Host: www.example.com
```

这才是在告诉服务端“我要哪个资源”。它经过 TLS 保护，再交给 TCP、IP 和链路层传送。

服务器接收、逐层处理后，由 Web 服务读懂请求并返回内容。浏览器得到 HTML，还可能继续请求图片、CSS、JavaScript 等资源。

**类比：** 物流系统负责把订单送达，商家拆开订单才知道你要什么；商家回寄货物时，仍通过物流系统按当时的路线发回。

### 第二部分：网络由哪些角色组成？

#### 1. 为什么要把计算机连接起来？

假设宿舍里有两台电脑，你想把自己电脑上的文件交给室友。最直接的办法是拿 U 盘拷过去。但如果对方在另一座城市，或者你们需要实时联机打游戏，总不能一直让快递员搬 U 盘。

**计算机网络解决的就是：让相互连接的计算机能够交换数据、共享资源。** 在实际使用中，通信往往发生在两端的应用程序之间，比如你的浏览器向服务器上的 Web 服务请求网页。

可以把它想成一套**物流系统**：每台主机都是可能寄件、收件的地点，通信链路负责运输，中间设备负责把东西交到合适的下一站。

- **数据通信：** 传文件、发消息、接收游戏状态，本质上都是交换数据。
- **资源共享：** 访问远程文件、使用网络打印机，相当于东西不在自己家里，也能通过网络使用。
- **应用协作：** 浏览器和网站服务器各做一部分工作，通过网络配合完成一次网页访问。

连上网络后，还要确定通信对象。就像有了公路，还得知道收货地址、收件部门，以及双方用什么格式填写订单。

#### 2. 网络由什么组成？—— 寄件点、运输线路和中转站

先分清主机、通信链路和交换设备的职责。

- **主机（端系统）：** 比如电脑、手机、服务器。可以类比物流系统两端的寄件点和收件点，应用程序在这里产生、使用数据。
- **通信链路：** 设备之间传递数据的通道。可以是有线，也可以是无线，相当于运输线路。
- **交换设备：** 把数据继续送向目的地。交换机、路由器都属于常见的中间设备，但它们依据的信息和负责的范围不同。

从互联网的组成看，还可以分成：

- **边缘部分：** 用户直接使用的主机及其应用。比如你打开 Chrome、服务器处理请求。
- **核心部分：** 把大量网络连起来的路由器和链路，主要承担数据转发。

**类比：** 你在网店下单、商家备货，属于两端的业务；快递集散中心把包裹转运过去，属于中间运输系统的工作。

#### 3. 互联网为什么叫“网的网”？

宿舍里的设备可以组成一个小网络，校园里又有校园网络，运营商还有自己的网络。这些网络继续互联，才构成我们使用的互联网。

```text
本机 → 家庭 / 校园网 → 运营商网络 → 其他网络 → 服务器所在网络
```

可以类比全国物流：县里的配送网、市里的中转网和跨省运输线路相互衔接，共同完成运输。

**核心原理：IP 提供共同的网络层规则，把不同底层传输技术的网络连接起来。**

### 第三部分：网络为什么需要协议和分层？

#### 1. 协议是什么？—— 双方都得认同的办事规矩

假设你给商家发一句“老样子”，但商家从来没见过你，它根本不知道该发什么。计算机通信也一样，双方要先约定好数据格式和处理规则。

**网络协议，就是通信双方为交换数据而遵守的规则。** 可以从三个方面理解：

- **语法：格式怎么写。** 像快递单规定收件人、地址、电话分别填在哪里。网络报文也要规定字段位置、长度和排列方式。
- **语义：内容是什么意思。** 像“到付”两个字意味着由收件人付钱。协议里的标志、编号也各有含义。
- **同步 / 时序：什么时候做什么。** 像先提交订单、再确认接单，按先后顺序配合。

网线解决传输介质的问题，协议规定通信行为。

#### 2. 为什么要分层？—— 让应用专注业务，底层负责传输

想象你开了一家网店。每收到一个订单，你都得亲自研究货车怎么发动、高速怎么选路、途中丢件怎么补发，还要负责客户沟通。这家店很快就没法经营了。

网络分层解决的就是这个问题：**把通信拆成几个层次，让应用专注业务逻辑，传输细节交给下层。**

于是应用和下面的层次分工。

- 应用负责表达“我要什么”。
- 下面的层次提供传输、寻址和交付等服务。
- 最底层把比特变成能够传播的信号。

实际写程序时，应用可以通过 socket 等接口收发数据，由操作系统协议栈、驱动和网卡继续完成后面的工作。

**底层意义：每层把一类问题处理好，通过接口向上提供服务。** 就像读写文件时直接调文件接口，不用自己去控制 SSD 里的电荷。

#### 3. 五层体系分别负责什么？—— 从下单到运输

这里采用学习中常用的五层模型（OSI 七层和 TCP/IP 四层只是划分粒度略有不同）。先对应到同一件事：你要向远方的一家店索取一份商品目录。

| 层次 | 物流类比 | 实际职责 |
| --- | --- | --- |
| 应用层 | 客户和商家约定订单怎么写 | 规定应用交换的信息及其含义，如 HTTP、DNS |
| 传输层 | 两端收发部门管理交付 | 为应用端点提供传输服务，如 TCP、UDP |
| 网络层 | 跨地区安排包裹去向 | 通过 IP 寻址和路由完成跨网络交付 |
| 数据链路层 | 当前这一段的装运和交接 | 在相邻节点之间传送帧 |
| 物理层 | 实际运输所依赖的道路和车辆 | 通过介质传输比特 |

同一层里的不同协议还会按需求分工，例如传输层的 TCP 提供可靠、有序的字节流，UDP 则只做轻量的报文交付。

#### 4. 协议、服务、接口有什么区别？

这三个词很容易背成一团。继续用快递理解：

- **协议：** 两地物流部门之间约定的交接规则，是同层双方的约定。
- **服务：** 物流公司向网店提供“帮你送货”的能力，是下层向上层提供的功能。
- **接口：** 网店在哪里、用什么方式提交寄件请求，是上下层交接的入口。

**同层之间讲协议，上下层之间讲服务和接口。** 两端应用看起来直接对话，真正的数据仍然要逐层向下，经物理传输，再在另一端逐层向上。

### 第四部分：数据怎样封装与解封装？

#### 1. 封装：每一层加上自己需要的信息

假设商家要寄一本书。书里写了什么，运输人员不需要读；但收件人是谁、最后送到哪里、当前装上哪趟车，就需要另外的标签。

网络发送数据也是这样。以 TCP、IP 和以太网为例：

![封装层次：上层数据装入 TCP 报文段，TCP 装入 IP 数据报，再装入以太网帧](/images/notes/computer-network/encapsulation-stack.svg)

**封装时，下层把上层交来的内容当作数据，再加上本层完成任务所需的控制信息。**

可以把嵌套关系画成：

```text
[以太网首部 | IP 首部 | TCP 首部 | 应用数据 | 以太网尾部]
```

实际传输时，一份较大的应用数据还会被拆成多个报文段，分别封装成帧发送。

#### 2. 解封装：到达哪一层，就处理哪一层的信息

收件时，物流人员先看运输标签，单位收发室再看收件部门，最后由具体的人打开信件。

接收端也会逐层处理：

```text
收到帧 → 取出 IP 数据报 → 交给 TCP 处理 → 应用取得数据
```

对于 HTTPS，还需要由 TLS 处理加密内容，应用才能取得 HTTP 信息。

**中间路由器只拆到网络层。** 普通 IP 转发依据目的 IP 决定下一跳，直接重新封装帧发走，无需拆开上层内容。

## 第二章：数据怎样逐跳传输

先把地址和交付过程分清，再看一个数据报经过各台设备时发生什么。例子中的子网判断先接受结论，第三章再推导它的计算方法。

### 第一部分：IP、MAC 与端口各管什么？

#### 1. IP：最终送到哪里？

可以把 IP 理解成包裹上用于跨网络交付的地址。路由器查看目的 IP，查询路由表，决定从哪个出口、交给哪个下一跳。

**类比：** 南昌的集散中心看到收货地址在北京，于是选择合适的北上线路。它负责决定下一站，不需要亲自送到收件人门口。

#### 2. MAC：眼前这一段交给谁？

在以太网场景中，MAC 地址用于当前链路上的帧交付。如果远端服务器不在本地子网，本机通常先把帧交给网关的接口。

于是同一次发送中会同时出现：

```text
目的 IP：最终服务器
目的 MAC：当前下一跳的接口
```

**类比：** 包裹里面的收货单一直写着最终地址，外面的转运标签则写着当前这一程交给哪个中转站。

已知本地链路上下一跳的 IPv4 地址，却不知道对应的 MAC 时，就需要 ARP。在没有有效缓存的简单场景中，本机会广播询问“谁拥有这个 IP”，由对应设备回复。

**ARP 只在本地链路上查询下一跳的 MAC。** 访问异地服务器时，本机先用 ARP 找本地网关的 MAC。

#### 3. 端口：到了这台主机，再交给谁？

一台服务器可能同时运行 Web、SSH 等服务。只知道 IP，就像只写了公司地址，还没有写收件部门。

端口帮助操作系统把数据交给相应的应用端点。例如 HTTPS 的默认服务端口是 `443`。

TCP 连接用双方的 IP 和端口（四元组）共同区分。

#### 4. 经过中转站，哪些信息会变？

先采用各段都是以太网、不经过 NAT 等额外处理的简单模型：

```text
电脑 → 路由器 R1 → 路由器 R2 → 服务器
```

- **源、目的 IP：** 保持不变，仍然指向通信两端。
- **源、目的端口：** 普通路由转发不改动。
- **MAC：** 每跨过一台路由器，重新按出口接口和下一跳封装。
- **TTL：** 每经过一台路由器减 1，同时更新 IP 首部校验和。

**补充对比：** 经过同一链路内的二层交换机时，MAC 保持不变；经过家庭出口的 NAT 时，源 IP 和端口会被改写。

### 第二部分：用快递模型理解转发

#### 1. 从家门口到收件人，中间到底发生了什么？

假设你从家里寄一本书到外地。包裹先交给本地网点，再经过不同的集散中心，最后交给收件人。**每个中转站看着最终收货地址，安排下一段运输。**

对应到网络，可以先画出这条主线：

```text
浏览器 → 本机 → 默认网关 R1 → 路由器 R2 → 服务器 → 服务端应用
寄件人 → 寄件点 → 本地集散中心 → 目的地集散中心 → 收件单位 → 收件部门
```

#### 2. 一件包裹上，为什么要同时保留三类信息？

| 包裹上的信息 | 网络中对应什么 | 解决的问题 |
| --- | --- | --- |
| 最终收货地址 | 目的 IP | 最终送到哪个网络中的目标接口 |
| 收件部门 | 目的端口 | 到达主机后，交给哪个应用端点 |
| 当前运输标签 | 目的 MAC | 当前以太网链路上，交给哪个下一跳接口 |

例如访问远端 HTTPS 服务时，第一帧可以同时写着：

```text
目的 MAC：本地网关的接口
目的 IP ：远端服务器
目的端口：443
```

**这三项各司其职：MAC 负责眼前这一跳交给网关，IP 负责跨网找到服务器，端口负责进服务器后找到服务进程。**

#### 3. 路由器像集散中心的分拣员

路由器收到帧后，先拆开旧的链路层外壳，查看里面的目的 IP 并查路由表，定好下一站后，再换上下一段链路的外壳发走：

```text
处理旧的链路层封装
    ↓
读取目的 IP，查询路由表
    ↓
确定出口与下一跳
    ↓
按下一段链路的规则重新封装并发送
```

**路由器只看目的 IP 在哪个网段，据此决定往哪条链路转。**

### 第三部分：跟着数据包走过每一跳

#### 1. 先搭一个能够完整观察的实验网络

下面使用一个内部实验网络：各段都是以太网，路由已经配置好，暂不考虑 NAT、隧道和分片。TCP 与 TLS 连接也已经建立，现在观察一段应用数据的发送。

![实验网络拓扑：A、R1、R2 与 S 通过三个不同子网的链路连接，路由器的入口与出口分别标注地址](/images/notes/computer-network/routed-network.svg)

路由器连接不同网络，每个接口都有独立的 MAC（图中简记为 `A`、`R1-入`、`R1-出`、`R2-入`、`R2-出`、`S`）。

#### 2. 第一跳：电脑为什么找网关的 MAC？

电脑 A 的本地网络是 `192.168.1.0/24`，服务器 `10.0.2.8` 不在其中。假设没有更具体的路由，本机选择默认网关 `192.168.1.1`。

确定下一跳之后，先查 ARP 缓存；没有有效记录时，再在本地链路广播查询网关的 MAC。

![第一跳帧：MAC 从电脑 A 指向 R1 入口，IP 与端口指向通信两端](/images/notes/computer-network/first-hop-frame.svg)

**流程顺序固定：先查路由定下一跳，再用 ARP 解析该下一跳的 MAC。**

#### 3. 第二跳：R1 收到了发给自己的帧，为什么还要继续转发？

因为 R1 只是这一跳的链路接收者，里面的 IP 数据报写的目的地是服务器 `10.0.2.8`。

R1 接收链路层交付的帧，取出 IP 数据报，发现目的 IP 是 `10.0.2.8`。查询路由表后，假设应通过 `10.0.12.1` 接口交给 R2 的 `10.0.12.2` 接口。

R1 处理 TTL、更新 IPv4 首部校验和，并在需要时用 ARP 取得 R2 对应接口的 MAC，重新封装：

![第二跳帧：MAC 从 R1 出口指向 R2 入口，IP 与端口保持不变，TTL 降为 63](/images/notes/computer-network/second-hop-frame.svg)

**源 MAC 填的是当前发包出口 `R1-出`，目的 MAC 填的是下一跳入口 `R2-入`。**

#### 4. 最后一跳：R2 把数据送到服务器

R2 查询路由表，发现 `10.0.2.0/24` 是直连网络，于是下一跳就是服务器本身。需要时，R2 查询服务器的 MAC，再发送最后一帧。

| 字段 | A → R1 | R1 → R2 | R2 → S |
| --- | --- | --- | --- |
| 源 MAC | A | R1-出 | R2-出 |
| 目的 MAC | R1-入 | R2-入 | S |
| 源 IP | 192.168.1.10 | 192.168.1.10 | 192.168.1.10 |
| 目的 IP | 10.0.2.8 | 10.0.2.8 | 10.0.2.8 |
| 源端口 | 50000 | 50000 | 50000 |
| 目的端口 | 443 | 443 | 443 |
| TTL（假设初值 64） | 64 | 63 | 62 |

**普通路由转发中，两端 IP 和端口保持不变；以太网帧头逐跳重封装，IP 首部的 TTL 逐跳减 1（减到 0 则丢弃，防止路由环路）。**

#### 5. 到服务器以后，为什么还要继续向上拆？

服务器发现目的 IP 属于本机，接着根据 IPv4 首部中的协议字段，把载荷交给 TCP。对于已经建立的 TCP 连接，再结合**源 IP、源端口、目的 IP、目的端口**（四元组）找到对应连接，把按序整理好的字节交给应用使用。

```text
以太网接收 → IP 本地交付 → TCP 连接与字节流处理 → TLS 处理 → HTTP 服务
```

多个客户端同时访问服务器的 `443` 端口时，内核正是靠四元组区分各自独立的连接。

服务器回复时，两端的 IP、端口方向对调，沿途仍逐跳选择路由、封装帧。

### 第四部分：交换机怎样完成本地交付？

#### 1. 交换机：在本地链路里，把帧送向合适的接口

![A、B 在同一子网与 VLAN，帧经二层交换机直接交付，不经过网关](/images/notes/computer-network/switch-local-network.svg)

普通二层交换机根据**目的 MAC 查询 MAC 地址表**，选择转发接口；它通过收到帧的源 MAC 学习“哪个地址接在哪个物理口上”。如果目的地址未知，通常会在同一 VLAN 内向其他接口泛洪；ARP 广播也会在这个范围内传播。

**经过二层交换机时，帧中的源、目的 MAC 保持原样。** 只有跨过路由器进入下一段链路时，才会重新封装 MAC。

#### 2. 同网段通信为什么直接找对方？

假设 A 为 `192.168.1.10/24`，B 为 `192.168.1.20/24`，两者接在同一 VLAN 中。

A 判断 B 在本地子网，直接用 ARP 取得 B 的 MAC，发送 `A → B` 的帧，由二层交换机直接转给 B。

#### 3. 路由器与最终主机，处理深度有什么不同？

| 角色 | 普通转发或接收时主要做什么 |
| --- | --- |
| 二层交换机 | 查看 MAC 地址表，在本地二层网络内转发帧 |
| 路由器 | 处理链路层封装，依据目的 IP 查路由，再封装发出 |
| 最终主机 | 接收本机的数据，继续交给 TCP / UDP 和应用处理 |

### 第五部分：NAT 为什么会改变地址？

#### 1. NAT：为什么家里的源 IP 和端口有时会变化？

家庭网络常用私有地址，例如 `192.168.1.10`。私有地址不能作为公网中的全局可路由地址使用，家庭出口常通过地址转换让多个设备共享公网 IPv4 地址。

以带端口转换的 NAPT 为例，映射可以示意为：

```text
内网端点 192.168.1.10:50000
              ↓ 出口转换
外网端点 203.0.113.8:62001
```

这里的 `203.0.113.8` 仅用于文档示例。设备记录映射关系，收到相应返回流量时，再转换回内网端点。

![NAPT出站修改源端点，回包按同一映射恢复内网目的端点](/images/notes/computer-network/napt-round-trip.svg)

**普通路由转发与 NAT 是两种功能，家庭路由器常常同时承担。**

## 第三章：子网与路由怎样决定下一跳

上一章已经看到数据需要选择下一跳。这一章追问：电脑凭什么判断目标在本地，以及怎样从路由表选出转发方向？

### 第一部分：IP 与掩码怎样划分网络？

#### 1. IPv4 地址本质上是什么？

IPv4 地址是一串 **32 位二进制数**。为了便于阅读，通常把它分成四组，每组 8 位，再写成十进制，每组范围是 `0～255`。

```text
192      .168      .1        .10
11000000 .10101000 .00000001 .00001010
```

IP 地址配置在具体的网络接口（网卡）上，一台多网卡设备可以拥有多个 IP。

#### 2. 为什么只看 IP，还不知道它属于多大的网络？

快递地址需要区分“配送区域”和“区域内的具体地点”。IP 也要区分**网络前缀**与**主机部分**，分界位置由子网掩码说明。

```text
地址：192.168.1.10
掩码：255.255.255.0
二进制掩码：11111111.11111111.11111111.00000000
```

在这里采用的连续掩码中，前面的 `1` 对应网络位，后面的 `0` 对应主机位。上例有 24 个网络位、8 个主机位，可以简写为 `192.168.1.10/24`。

**掩码是一把划分地址的尺子。** `/24` 表示前缀长度。

#### 3. CIDR 表示法：分界位置由前缀长度决定

CIDR（无类别域间路由）直接用“网络前缀 + 前缀长度”描述地址块。

| 前缀长度 | 子网掩码 | 主机位数 | 地址总数 |
| --- | --- | --- | --- |
| /16 | 255.255.0.0 | 16 | 65536 |
| /24 | 255.255.255.0 | 8 | 256 |
| /25 | 255.255.255.128 | 7 | 128 |
| /26 | 255.255.255.192 | 6 | 64 |
| /27 | 255.255.255.224 | 5 | 32 |

例如 `/26` 的最后一个字节是 `11000000`，即第四个字节的前 2 位仍属于网络，后 6 位才属于主机。

---

### 第二部分：怎样判断目标在不在本地？

#### 1. 网络地址为什么等于 IP AND 子网掩码？

按位与的规则是：**两位都是 1 才得到 1。** 所以某位与 `1` 运算时保留原值，与 `0` 运算时清零。

```text
IP：   11000000.10101000.00000001.00001010
掩码： 11111111.11111111.11111111.00000000
AND：  11000000.10101000.00000001.00000000
结果： 192.168.1.0
```

掩码保留了网络部分、清除了主机部分，得到的 `192.168.1.0` 就是网络地址；连同前缀长度写成 `192.168.1.0/24`，表示这个地址块。

#### 2. 判断目标是否在本地子网，要用谁的掩码？

站在发送主机的视角，使用**本机接口的掩码**分别处理本机 IP 和目标 IP，比较结果（以单网卡直连子网为例）：

```text
本机：192.168.1.10/24
本机 IP AND 掩码 = 192.168.1.0

目标 B：192.168.1.20
目标 IP AND 本机掩码 = 192.168.1.0 → 在本地子网

目标 S：10.0.2.8
目标 IP AND 本机掩码 = 10.0.2.0   → 不在本地子网
```

本机发包时只拿自己的掩码做按位与。若两端掩码配错不一致，就会出现一方直接发 ARP、另一方却走网关的单向不通现象。

#### 3. 前三段相同，为什么也可能不同网段？

假设三台主机都配置 `/26`，每个地址块有 64 个地址：

| 主机 | IP | 所属网络 |
| --- | --- | --- |
| A | 192.168.1.100/26 | 192.168.1.64/26 |
| B | 192.168.1.120/26 | 192.168.1.64/26 |
| C | 192.168.1.130/26 | 192.168.1.128/26 |

`100` 和 `120` 都落在 `64～127`，`130` 却落在 `128～191`。所以 A、B 同网段，A、C 不同网段。

**是否同网段完全由 IP 与前缀掩码决定。**

---

### 第三部分：怎样算出子网的地址范围？

#### 1. 一个子网里，哪些地址通常不能分配给普通主机？

在常规 IPv4 子网中，保留网络位不变：

- **主机位全 0：网络地址。** 用来表示整个网络。
- **主机位全 1：广播地址。** 用来表示向这个子网广播。
- **中间的地址：可用主机地址。** 可以分配给终端或路由器接口（网关也要占其中一个可用地址）。

例如 `192.168.1.0/24` 的网络地址是 `.0`，广播地址是 `.255`，通常可用范围是 `.1～.254`。

```text
主机位数 h = 32 - 前缀长度
地址总数   = 2^h
通常可用主机地址数 = 2^h - 2
```

#### 2. 从 /24 变成 /25，为什么正好分成两半？

原来的 `/24` 有 8 位主机位。借出其中一位作为网络位后，新增加的网络位可以取 `0` 或 `1`，于是分成两个 `/25` 子网，每个保留 7 位主机位。

| 子网 | 网络地址 | 广播地址 | 通常可用地址 | 可用数量 |
| --- | --- | --- | --- | --- |
| 192.168.1.0/25 | 192.168.1.0 | 192.168.1.127 | 192.168.1.1～192.168.1.126 | 126 |
| 192.168.1.128/25 | 192.168.1.128 | 192.168.1.255 | 192.168.1.129～192.168.1.254 | 126 |

**前缀越长，单个地址块越小。** 从 `/24` 划成两个 `/25`，地址总数仍是 256，但两个子网分别保留网络地址和广播地址，通常可用地址合计变为 252。

#### 3. 完整算例：192.168.10.70/26 属于哪个网络？

先看前缀：`/26 = 24 + 2`，最后一个掩码字节为 `11000000`，也就是 `192`，完整掩码为 `255.255.255.192`。

主机位有 `32 - 26 = 6` 位，每块共 `2^6 = 64` 个地址。最后一段按 64 分块：

![最后字节按 64 分块，70 落在 64 到 127 范围内，网络地址为 .64](/images/notes/computer-network/subnet-address-blocks.svg)

也可以用二进制复核最后一个字节：

```text
70：   01000110
192：  11000000
AND：  01000000 = 64
```

由此确定网络地址、广播地址及可用主机地址。

- **网络地址：** `192.168.10.64`，所属网络写作 `192.168.10.64/26`。
- **广播地址：** `192.168.10.127`，即把后 6 位全部置为 1。
- **可用范围：** `192.168.10.65～192.168.10.126`。
- **通常可用数量：** `64 - 2 = 62`。

#### 4. 速算：用块大小确定起点和终点

对于 `/25～/30` 这类分界落在最后一个字节的题目：

```text
块大小 = 256 - 掩码最后一个字节
网络地址末段 = 向下取整(IP 末段 ÷ 块大小) × 块大小
广播地址末段 = 网络地址末段 + 块大小 - 1
```

例如 `/27` 的掩码末段是 `224`，块大小为 `32`，起点依次为 `0、32、64、96、128、160、192、224`。

**如果分界落在第三个字节（如 `/17～/23`），就在第三个字节上用同样的块大小公式，第四个字节直接从 `0` 到 `255`。** 例如 `/20` 的掩码是 `255.255.240.0`，在第三个字节按 `256 - 240 = 16` 分块，`192.168.18.70/20` 的网络地址是 `192.168.16.0`，广播地址是 `192.168.31.255`。

### 第四部分：怎样选择网关与路由？

#### 1. 默认网关为什么通常要和本机在同一个子网？

默认网关是本机在使用默认路由时，要先交付数据的路由器接口。它就像本地揽件站：**你至少要能把包裹先送到它手里，它才有机会替你送往远方。**

在常规以太网直连配置中，`192.168.1.10/24` 可以使用同链路的 `192.168.1.1` 作网关。若填成不在同一链路的 `10.0.0.1`，本机就无法在二层把帧交给这个下一跳。

网关选择遵循同一个要求：**下一跳在所选链路上可直接到达**。

#### 2. 默认网关与默认路由有什么区别？

- **默认网关：** 强调“交给谁”，例如下一跳 `192.168.1.1`。
- **默认路由：** 强调“没有更具体的匹配时采用哪条规则”，IPv4 中写作 `0.0.0.0/0`。

主机也有路由表。例如主机中的一条默认路由可以表示为：

```text
目的前缀 0.0.0.0/0 → 下一跳 192.168.1.1 → 本机以太网接口
```

`/0` 表示前缀长度为 0，能匹配所有 IPv4 目的地址，**在没有匹配到其他具体路由时作为兜底规则生效。**

#### 3. 为什么路由表通常按网络前缀组织？

集散中心按区域组织发车方向，路由表也用一个网络前缀代表一整块目的地址（如 `10.0.2.0/24`），需要精确到单台主机时再配 `/32` 主机路由。

#### 4. 多条路由都匹配时，为什么选最长前缀？

假设路由表中有以下规则，出口和下一跳均已正确配置：

| 目的网络前缀 | 转发方向 |
| --- | --- |
| 10.0.0.0/8 | 出口 A |
| 10.1.0.0/16 | 出口 B |
| 10.1.2.0/24 | 出口 C |
| 0.0.0.0/0 | 出口 D |

目的 IP 是 `10.1.2.100` 时，这四条都匹配，但应选择 `/24`，因为它限制的地址位最多、描述的范围最具体。这就是**最长前缀匹配**。

可以类比“某省”“某市”“某区”三条配送规则同时匹配上收货地址时，优先走最具体的那一条。

![嵌套网络范围显示最长前缀匹配：10.1.2.100选/24，10.1.3.100选/16](/images/notes/computer-network/longest-prefix-match.svg)

```text
10.1.2.100 → 匹配 /8、/16、/24、/0 → 选 /24 → 出口 C
10.1.3.100 → 匹配 /8、/16、/0      → 选 /16 → 出口 B
10.2.3.100 → 匹配 /8、/0           → 选 /8  → 出口 A
192.0.2.10 → 只匹配 /0             → 选 /0  → 出口 D
```

#### 5. 把子网、路由、ARP 和封装接成一条完整流程

只有直连路由和默认路由时，可以先用这个简化模型理解：

![判断下一跳并解析 MAC：目标主机或默认网关先确定，ARP 缓存命中直接使用，未命中再查询](/images/notes/computer-network/next-hop-resolution.svg)

**完整流程是：先按最长前缀匹配路由表定出下一跳，再用 ARP 拿到该下一跳的 MAC，封装成帧发往对应链路。**

到这里，子网掩码用来划定直连网段范围，路由表决定下一跳交给谁，ARP 把下一跳的 IPv4 地址映射成 MAC，链路层完成当前这一段交付。

## 第四章：子网怎样划分，路由怎样聚合

第三章解决了“一个 IP 属于哪个子网”。这一章换到网络管理员的视角：**手里只有一块地址，怎样分给大小不同的部门？分出去的网络，又怎样在路由表里用更少的规则表示？**

### 第一部分：为什么需要大小不同的子网？

#### 1. 一个大院子住得下，为什么还要分区域？

假设学校有地址池 `192.168.10.0/24`，常规可用主机地址共 254 个。四个部门分别需要：

| 部门 | 需要容纳的主机数 |
| --- | --- |
| A：计算机实验室 | 100 |
| B：行政办公室 | 50 |
| C：图书馆 | 20 |
| D：监控系统 | 10 |

合计 180 个，总数虽然装得进一个 `/24`，但学校通常要按部门管理地址、控制部门间访问，并配合 VLAN 隔离二层广播域。

**类比：** 整栋楼装得下所有人，但实际办公还是会按部门分房间，方便管理边界，房间大小也要按各部门人数来定。

#### 2. VLSM：大部门分大房间，小部门分小房间

如果把一个 /24 均分成四个 /26，每个子网只有 62 个常规可用地址，实验室的 100 台主机就放不下。

**VLSM**（Variable Length Subnet Mask，可变长子网掩码）允许在同一地址块中使用不同长度的子网前缀。A 可以用 /25，B 用 /26，小部门再用 /27、/28。

**核心思想：按各部门的实际主机数选择对应大小的地址块。**

---

### 第二部分：根据主机数量，怎样算出前缀长度？

#### 1. 先问要多少主机位，再求前缀

对于这里讨论的常规 IPv4 子网，设需要 H 个可分配地址，主机位有 h 位，就要满足：

```text
2^h - 2 ≥ H
前缀长度 n = 32 - h
```

在满足容量的 h 中选最小值，就得到能够容纳需求的最小常规地址块。减去的两个地址是网络地址和定向广播地址。

例如 A 需要 100 个：

- 6 位主机位：64 个总地址、62 个可用地址，不够。
- 7 位主机位：128 个总地址、126 个可用地址，够用。
- 因此分配 `/25`。

**类比：** 储物箱只有 16、32、64、128 格这几种规格，要放 100 件东西，就选 128 格的那一档。

#### 2. 把四个部门的容量先算好

| 部门 | 需求 | 主机位 h | 前缀长度 | 总地址数 | 常规可用地址数 |
| --- | --- | --- | --- | --- | --- |
| A | 100 | 7 | /25 | 128 | 126 |
| B | 50 | 6 | /26 | 64 | 62 |
| C | 20 | 5 | /27 | 32 | 30 |
| D | 10 | 4 | /28 | 16 | 14 |

如果题目给的“需求数”只算了终端电脑，分配时别忘了把路由器网关接口那 1 个地址也算进 `H` 里（上表按已包含网关接口计算）。

### 第三部分：完整做一次 VLSM 分配

#### 1. 为什么通常先分最大的？

大地址块对起点的对齐要求更严。先排好大块，再把小块填进剩余空间，最容易一次排顺。

因此从需求最大的 A 开始，按 A、B、C、D 的顺序分配。

#### 2. 从地址池起点开始排

地址池是 `192.168.10.0/24`。下面表中后三列只写最后一个字节，前面均为 `192.168.10`：

| 部门 | 分配的子网 | 整块占用范围 | 可用主机范围 | 广播地址 |
| --- | --- | --- | --- | --- |
| A | 192.168.10.0/25 | .0～.127 | .1～.126 | .127 |
| B | 192.168.10.128/26 | .128～.191 | .129～.190 | .191 |
| C | 192.168.10.192/27 | .192～.223 | .193～.222 | .223 |
| D | 192.168.10.224/28 | .224～.239 | .225～.238 | .239 |
| 留作扩展 | 192.168.10.240/28 | .240～.255 | .241～.254 | .255 |

A 占用 128 个地址后，下一个空闲地址是 .128；B 再占 64 个，下一块从 .192 开始，依次继续。

![VLSM按128、64、32、16、16个地址分配一个/24，各块标明网络、主机与广播地址](/images/notes/computer-network/vlsm-address-allocation.svg)

**划分出去的整块范围（如 A 的 `.0～.127`）都归该子网所有，下一块要从 `.128` 往后排。**

#### 3. 为什么 B 不能从 .130 开始？

/26 有 6 个主机位。作为网络地址，这 6 位必须全部为 0。只看最后一个字节：

```text
网络位 | 主机位
  00   | 000000  →   0
  01   | 000000  →  64
  10   | 000000  → 128
  11   | 000000  → 192
```

因此同一个 /24 内，/26 的网络地址只能从 .0、.64、.128、.192 开始。

像 `192.168.10.130/26` 这样主机位不全为 0 的写法，表示的是 `192.168.10.128/26` 这个子网里的一台主机接口地址。

**类比：** 地址块像已经画好固定格线的停车区，`.128～.191` 是其中一个固定车区，130 号只是里面的一个车位。

### 第四部分：CIDR 路由聚合（把相同方向的配送规则合并）

#### 1. 已经分成小网络，为什么还要合起来？

假设一台上游路由器有四条路由：

```text
192.168.8.0/24  → R1
192.168.9.0/24  → R1
192.168.10.0/24 → R1
192.168.11.0/24 → R1
```

四个网络都经过 R1，到这里可以问：能不能用一条规则覆盖它们？

**类比：** 四个相邻片区都由同一个集散中心负责，上级站点可以只记录一条覆盖整个区域的规则，到了下级再细分。这样能减少需要维护和传播的路由表项。

#### 2. 找公共前缀，算出 /22

前两个字节 `192.168` 已经相同，占 16 位。再看第三个字节：

```text
 8 = 000010 | 00
 9 = 000010 | 01
10 = 000010 | 10
11 = 000010 | 11
       共同 6 位
```

共同前缀长 16 + 6 = 22 位，所以可以准确汇总为：

```text
192.168.8.0/22
掩码：255.255.252.0
范围：192.168.8.0 ～ 192.168.11.255
```

这个范围恰好是四个原 /24 的并集。

#### 3. 连续四个 /24，什么情况下才能合成一个 /22？

必须满足二进制边界对齐。`/22` 在第三字节的块大小是 4，起点只能是 `0、4、8、12……`。如果拿第三字节为 `9、10、11、12` 的四个 `/24` 去求公共前缀，它们跨过了 `12` 这条分界线，最小只能用 `192.168.8.0/21`（覆盖 `8～15`）包住，会把 `8、13、14、15` 四个不在列表里的网段也卷进来。

![CIDR对齐：8至11可汇总为/22，9至12跨边界，/21会额外覆盖四个/24](/images/notes/computer-network/cidr-aligned-aggregation.svg)

#### 4. 划分与聚合的方向正好相反

| 操作 | 前缀长度 | 单个前缀覆盖的范围 | 解决的问题 |
| --- | --- | --- | --- |
| 子网划分 | 变长，例如 /24 → /26 | 变小 | 怎样分配和管理地址 |
| 路由聚合 | 变短，例如四个 /24 → /22 | 变大 | 怎样用更少规则描述去向 |

### 第五部分：汇总规则与具体规则怎样一起使用？

#### 1. 大区域统一配送，小区域可以另设例外

假设路由表里同时有：

| 目的前缀 | 下一跳 |
| --- | --- |
| 192.168.0.0/16 | A |
| 192.168.10.0/24 | B |
| 192.168.10.128/25 | C |
| 0.0.0.0/0 | D |

目标 `192.168.10.150` 同时匹配四条规则，最终选择 /25，交给 C。

**类比：** “整个园区交给 A”“10 号楼交给 B”“10 号楼东半边交给 C”都符合地址，真正送往东半边时，采用最具体的安排。

因此聚合与最长前缀匹配可以配合：用短前缀描述大范围，再让更长前缀处理具体区域。

#### 2. 每一跳路由器都查自己的路由表

源主机查自己的路由表定出第一跳；数据包到了下一台路由器后，那台路由器再查**它自己的路由表**匹配目的 IP，定出下一跳接口，接着用 ARP 拿那个接口的 MAC 封装发走。
