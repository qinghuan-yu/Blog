最近将明日方舟的官网复刻到本地，重新整理了页面结构、资源和交互代码。复刻围绕六个全屏分区展开：从构图、字体和裁切，到分区揭幕、人物切换与粒子聚散，逐项对照原站。

最初的本地版本沿用了官网公开交付的脚本和样式。确认资源能够完整加载后，使用 React 和 Vite 重建源码。

大炎主题是回到大一时的作业，完成当时没做完的事。

## 观察页面与整理资源

### 记录页面状态

采集使用 Playwright 驱动 Chrome，保存桌面截图、渲染后的 HTML 和网络响应，再切到 390×844 的手机视口。截图用于比对比例和裁切，HTML 用于辨认层级，CSS 用于分析样式和交互，网络记录用于定位动态加载的资源。

### 沿引用关系完成本地化

首页加载完成时，部分详情图片和脚本分块尚未请求。让codex使用 Python 整理 HTML、CSS、JavaScript、接口快照和请求清单中的链接，再沿引用关系补齐资源，包括 Webpack 分块映射和 HLS 播放清单。

CSS 中的字体和背景图、脚本中的图片地址、媒体清单中的相对路径都随之重写。本地页面通过 `/vendor` 读取这批资源。

路径检查需要覆盖实际入口。有的遗漏在首屏看不出来，切换分类或打开详情后才会出现，然后逐个访问人物、分类、详情和媒体入口，核对请求结果。

视频保留了首页背景资源。官网的 20 部完整宣传片和玩法视频体量较大，使用 FFmpeg 从已有首页分片生成约 12 秒的循环 MP4，配合原有封面供长视频入口预览。

### 移除原站业务依赖

初始版本通过本地兼容层处理 SDK 依赖，移除监测初始化，将固定展示的数据保存为静态快照。登录、下载等业务入口随后从页面中移除。

这一步同时涉及首屏 HTML 和客户端组件。只修改其中一处，旧按钮可能先显示，再在客户端接管页面时消失。删除按钮后，原容器承担的间距也需要重新安排，才能保持标题和返回区的位置。

完成这一阶段后，页面的展示与交互已经能够在本地运行。随后拆分源码，替换原有交付包的组织方式。

## 重建源码与布局

将原来的 SSR/RSC 入口替换为 Vite 的 HTML 入口和 React 根节点，按六个分区重建组件。正文、人物与媒体内容移入数据文件，粒子场景单独放入动画模块。

项目使用 React 19、Vite 6、Three.js 和 Swiper。目录按页面、数据与动画分开：

```text
src/
  App.jsx                 页面装配与分区状态
  sections/               六个全屏分区
  components/             导航、过渡、详情和原图浏览
  hooks/                  分区导航与媒体查询
  data/                   页面内容与素材出处
  animations/             粒子场景、目标点与悬停形变
  styles/                 分区样式与主题样式
public/assets/            图片、字体、纹样和音频
```

分区在首次访问时加载，访问后保留组件状态。返回人物页时，之前选择的角色和立绘阶段仍然保留。各分区 CSS 统一在入口导入，固定样式的覆盖顺序。

### 构图比例

官网的顶部导航、右侧编号、左侧信息区与主体画面之间有相对固定的比例。沿用视口宽度换算根字号的方式，以 `rem` 描述主要尺寸，使位置与间距一起缩放。

```css
:root {
  font-size: calc(100vw / 120);
}

@media (orientation: portrait) {
  :root {
    font-size: calc(100vw / 46.875);
  }
}
```

竖屏下另行安排导航、立绘和正文，较矮的横屏则缩减间距。页面主体使用 `100dvh`，高度随动态视口变化。

### 全屏揭幕与内部滚动

分区切换时，外层容器的宽度从 0 展开到 100%，内部内容保持 `100vw`。外层负责裁切，内层保持完整尺寸。这样在揭幕过程中，文字和图片的位置不变，只有可见范围发生变化。前进与后退分别使用对应的展开方向。

导航由 `useSectionNavigation` 统一管理。地址 hash 记录当前分区，导航点击、滚轮、触摸和 PageUp/PageDown 都更新同一套状态。切换之间留出间隔，避免一次滚轮惯性连续翻过多屏。

详情、弹窗和标记为 `data-scrollable` 的区域处理自己的滚动。未激活分区使用 `inert`，隐藏的按钮和链接随之退出交互。全局粒子画布通过 React portal 挂入独立的 `#world-effects` 层，跨越分区显示，不受单屏揭幕容器的裁切。

## 还原切换过程

第一轮重写之后，静态画面已经接近，切换时仍能看出差别。官网的一次内容更换包含退出、遮罩移动、内容替换和入场，标题与辅助文字之间也有延迟。将这些过程重新拆开，按原站的先后关系衔接。

### 退出、替换与入场

`ContentTransition` 分别保存当前显示的内容与最新请求的内容。收到切换请求后，先让当前画面退出，再替换内容，等待 React 提交渲染，最后开始入场。

```text
选择新内容
  → 当前画面退出
  → 替换为最新请求的内容
  → React 提交渲染
  → 新画面进入
  → 回到稳定状态
```

透明度和位移由 Web Animations API 控制，渲染后的入场通过 `useLayoutEffect` 衔接。分类列表、人物介绍与立绘复用这套过程；章节编号、世界观标题和说明文字则分别设置延迟。部分缓动曲线采样成 CSS `linear()`，使不同动画实现的速度变化接近。

连续点击时，当前画面可能尚未完成入场。此时读取计算样式，从这一帧的透明度和位置继续退出。如果先重置到完全可见、零位移，再播放退出，就会出现跳动。退出期间收到的后续选择只更新最新目标，结束后直接显示这一项。

### 等待图片解码

人物切换还受图片加载影响。立绘地址已经更新，图片却未必能够立即绘制。在提交选择之前调用 `Image.decode()`，并为每次请求递增编号，只让最新请求更新页面。

```js
const ticket = ++requestId;
await decodeArtwork(nextImage);

if (ticket !== requestId) return;
commitSelection(nextSelection);
```

请求编号处理的是异步返回顺序：较早的选择即使较晚完成解码，也不会覆盖后来的选择。当前立绘准备好后，再预解码其余立绘，加载结果进入缓存。

立绘容器保持固定尺寸，每张图片分别配置缩放和平移。不同立绘的透明边界和人物重心差异较大，统一倍率仍会造成切换时的位置偏移。

### 入场结束时的透明度突变

背景放大的立绘曾在切换结束时突然变暗。原因是同一个元素的 `opacity` 受两套规则控制：静态样式设为 `.24`，入场动画却从 0 动到 1。动画撤销后，透明度恢复 `.24`，最后一帧便出现了突变。

将背景固定的灰度和透明度移入滤镜，将元素的 `opacity` 留给过渡动画：

```css
.operator-illustStyled .operator-img {
  filter: grayscale(1) opacity(.24);
}
```

滤镜始终保留背景的基础强度，过渡只控制它的显隐。入场结束后，动画值与静态样式能够连续衔接。

## 重建粒子与悬停效果

### 粒子聚散与换形

粒子场景使用 `THREE.Points`。预先分配一万个粒子的位置与颜色缓冲，为每个粒子保存不同的靠近速度。目标模型提供位置和颜色，当前值逐帧向目标靠近。

一维位置更新可写成：

```js
const blend = 1 - (1 - 1 / speed) ** frames;
position += (target - position) * blend;
```

`frames` 是实际帧间隔相对 60 Hz 的换算值，并设有上限。靠近比例随帧间隔调整，使不同刷新率下的运动速度接近。各粒子的速度不同，收拢便有先后；颜色和透明度也逐步趋近目标。

换形时保留当前位置，更换并重新排列目标点。粒子由当前图案直接移动到下一幅图案，画布和缓冲区继续复用。鼠标附近加入随距离衰减的排斥力；指针离开后，粒子重新向目标靠拢。

运动计算在 CPU 上进行，更新后的数组交给 GPU 绘制。顶点着色器负责投影与点大小，片元着色器将粒子颜色与点精灵纹理相乘。

模型与纹理会缓存，WebGL 像素比最高取 2。标签页隐藏时暂停渲染，离开场景后完成消散再停止，销毁时释放几何体、材质与纹理。减少动态效果的设置会简化运动，WebGL 初始化失败时显示静态图。

### 悬停纹样的跟随与形变

列表旁的悬停纹样由细分平面网格承载。图案与鼠标之间的位置差形成跟随速度，再用速度驱动网格弯曲，以及红、绿、蓝通道不同幅度的纹理采样偏移。移动时的拉扯和色散由此产生。

这个图案最初过大。原始网格为 1000 个单位，直接使用当前相机投影会占据过多空间。按视口将显示尺寸限制在约 140～220 个 CSS 像素，再换算网格缩放，并约束它与屏幕边缘的距离。

## 在复刻基础上改为大炎主题

页面与交互稳定后，曾尝试改为个人主页，随后回到大一时的旧作。改造沿用官网的六屏构图、导航和运动方式，主要调整内容、素材与配色。

### 页面与素材

六个分区分别改为序篇、风物、人物、舆图、视听和缘起。人物页选用年、夕、令、黍、重岳，城市内容围绕百灶、勾吴、大荒城、尚蜀和玉门组织。

首页换为山岳背景，原字形遮罩改为 `YAN`，保留分层切面与延迟显现。背景缓慢缩放，另用 Canvas 2D 绘制少量尘点。细线、坐标、编号和英文标记继续保留，配色调整为墨黑、纸色和暖金。

![大炎改造后的首页：山岳背景、竖排题字与 YAN 切面遮罩](/images/notes/yan-chronicles/dayan-home.png)

场景共 20 张，其中 9 张沿用旧工程，11 张从 PRTS 补充。五名人物各使用两阶段立绘与一个头像，共 15 份素材。城市介绍参考《相见欢》《画中人》《怀黍离》《将进酒》《登临意》等资料。

城市数据集中在 `chapters.js`，包含名称、介绍、图片数组和出处，再由 `dayan.js` 生成轮播、分类、专题与舆图内容。图库使用整组图片，轮播取第一张作为封面，列表根据数组长度显示数量。

标题沿用旧作的齐伋体，正文使用思源黑体可变字体，声明 `font-weight: 250 900`，并设置 `font-synthesis: none`。立绘分别调整前景位置与背景取景，左侧用渐变遮罩保留文字的可读性。

![大炎改造后的人物页：夕的前景立绘、背景放大图与档案文字](/images/notes/yan-chronicles/dayan-character.png)

### 将龙纹与五城图案转为粒子

舆图总览使用旧作龙纹，五城分别制作 SVG 纹样：百灶取宫阙与炉火，勾吴取水巷与石桥，大荒取稻穗与田畴，尚蜀取山峦与亭阁，玉门取塞垣与远日。

保留粒子场景接收目标点的接口，增加图片采样模块。PNG 或 SVG 解码后绘制到离屏 Canvas，按网格步长取样，格内加入可重复的随机偏移，再将坐标转换为以画布中心为原点。

龙纹原图带有不透明黑底，只检查 alpha 会把方形背景一并采入。因此将 RGB 均值作为亮暗权重，与 alpha 相乘后过滤：

```js
const brightness = (r + g + b) / 3;
const effectiveAlpha = alpha * brightness / 255;

if (effectiveAlpha > 36) {
  points.push([x, y, Math.round(effectiveAlpha)]);
}
```

黑底权重低，浅色线条保留。随后调整目标点的 RGB，为各城设置纸色与暖金色，位置、透明度及运动参数继续复用。

![大炎改造后的舆图：龙纹粒子与勾吴水巷石桥悬停图案](/images/notes/yan-chronicles/dayan-world.png)

城市专题补入多图浏览、原图弹窗和键盘切换。音乐沿用《赴大荒》，顶部循环播放与视听区播放器互斥，音频由点击触发。

## 验证与项目资料

开发中分别检查静态画面和实际操作。静态对照使用相同视口与内容状态，比较比例、裁切和字体；动画检查进入、退出与中间帧，并连续切换分类、人物及立绘阶段，观察是否闪回或复位。

检查覆盖桌面、手机竖屏和较矮横屏，以及详情进退、原图浏览、音乐互斥和减少动态效果。截图与行为检查使用 Playwright，修正后再验证生产构建。

代码保存在 [yan-chronicles](https://github.com/qinghuan-yu/yan-chronicles)，当前 `main` 为大炎版本。本地运行使用：

```sh
npm install
npm run dev
```

生产预览先执行 `npm run build`，再执行 `npm run preview`。
